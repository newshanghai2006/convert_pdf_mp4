# AI PDF解说视频生成器（《大众电影》式杂志专用）

把一本 PDF 杂志自动变成带 AI 旁白的解说视频（MP4）。上传 PDF → 自动提取文字 →（纯图片则 OCR/AI OCR）→ 编辑旁白 → 调参数 → 一键生成。

参考样例见 `sample/`：输入 `sample_in.pdf`（46 页扫描件），输出 `sample_out.mp4`（约 4 分 39 秒）。

---

## 一、文件结构

所有文件都在本应用目录（本文档所在目录）下：

```
mk_dzdy/
├── app.py            # Flask 服务与 HTTP 接口（程序入口）
├── pipeline.py       # 参数化生成管线（抽页/合成帧/标题卡/旁白/合成）
├── index_html.py     # 前端网页（上传、调参、编辑旁白、进度、下载）
├── _ocr_worker.py    # OCR 子进程（EasyOCR/RapidOCR/PaddleOCR，可断点续跑）
├── _selftest.py      # 端到端自检脚本（构造测试 PDF 跑通全流程）
├── font.ttf          # 中文字体（楷体），标题卡与文字渲染用
├── sample/           # 样例：sample_in.pdf / sample_out.mp4
└── tasks/            # 运行时自动生成：每个任务一个子目录，存放上传PDF/中间帧/成品MP4
```

成品视频默认在 `tasks/<任务ID>/output.mp4`。

## 二、环境准备与安装（第一次在新电脑上跑，请照这里做）

本程序依赖：**Python 3.14** + 若干 Python 库 + **ffmpeg**（含 ffprobe）。缺任何一个都会跑不起来。

### 1) 安装 Python 3.14

- Windows：到 https://www.python.org/downloads/ 下载 3.14 安装，安装时**勾选 "Add python.exe to PATH"**。
- 装好后开一个新终端验证（下面命令能打印版本号即可）：
  ```bat
  py -3.14 --version
  ```
  若没有 `py` 启动器，用 `python --version` 确认是 3.14，下文命令把 `py -3.14` 换成 `python` 即可。

### 2) 安装 ffmpeg（含 ffprobe）

- Windows 最简单：
  ```bat
  winget install Gyan.FFmpeg
  ```
  或到 https://www.gyan.dev/ffmpeg/builds/ 下载 full build，解压后把其中 `bin` 目录加入系统 PATH。
- **新开一个终端**验证（两条都要能打印版本）：
  ```bat
  ffmpeg -version
  ffprobe -version
  ```
  > 装完 ffmpeg 一定要**重开终端**，否则 PATH 不生效——这是"运行无显示/合成失败"的常见原因。

### 3) 安装 Python 依赖库

```bat
py -3.14 -m pip install --upgrade pip
py -3.14 -m pip install flask PyMuPDF Pillow edge-tts numpy
```

**本地 OCR 是可选的**（只有纯图片/扫描 PDF 才需要）。三种本地引擎按需安装：

```bat
py -3.14 -m pip install easyocr                # EasyOCR，默认
py -3.14 -m pip install rapidocr_onnxruntime   # RapidOCR，ONNX Runtime
py -3.14 -m pip install paddleocr paddlepaddle # PaddleOCR，中文优化
```

网页里的「OCR 引擎」下拉框会选择实际使用的本地引擎；不使用纯图片 PDF 时可以不安装这些 OCR 包。
PaddleOCR 的 Python 3.14 wheel 若暂不可用，建议在 Python 3.11/3.12 独立环境中运行本项目。

### 4) 一键自检环境是否就绪

```bat
py -3.14 app.py
```

启动时会先打印**自检信息**，逐项告诉你 ffmpeg / ffprobe / flask / fitz / PIL / edge-tts 以及三种 OCR 引擎依赖是否 OK：

```

  ffmpeg : OK C:\...\ffmpeg.EXE
  ffprobe: OK C:\...\ffprobe.EXE
  flask   : OK
  fitz    : OK
  PIL     : OK
  edge_tts: OK
  easyocr : OK
  rapidocr_onnxruntime: OK
  paddleocr : OK
  paddle   : OK
==================================================
启动服务: http://127.0.0.1:5005
 * Running on http://127.0.0.1:5005
```

哪一项显示"缺失"，就按上面的第 1~3 步补装。

### 5) 打开网页

用浏览器打开 **http://127.0.0.1:5005** 即可使用（仅本机访问）。
> 若"运行无显示"：先确认第 4 步的自检信息有没有打印出来（没有→多半是 Python 没装好/版本不对）；
> 若自检打印了但浏览器打不开→确认端口 5005 没被占用或被防火墙拦截。

### 网络要求（重要）

- **配音（TTS）需要联网**：edge-tts 会调用微软语音服务（`speech.platform.bing.com`）。
  若公司网络/防火墙/代理把它挡住，就会报"无法连接"的错——见「八、常见问题」。
- **OCR 首次需要联网**：easyocr 首次运行会下载识别模型（约 100+ MB）到 `~/.EasyOCR/model/`，
  下载后即可离线使用。

### 日常启动（环境已装好后）

```bat
py -3.14 app.py
```

浏览器打开 **http://127.0.0.1:5005**。

## 三、使用步骤（网页上四步）

1. **选择 PDF + 基本参数**
   - 拖入或点击选择 PDF 文件。
   - 设置「每片段时长」「每片段页数」「封面时长」。
   - 可选「按解说词自动延长片段时长」（见「四、新功能」）。
   - 可选「**选择参与制作的页码**」：只用 PDF 里的某些页。支持 `~` 或 `-` 表示范围、逗号分隔，
     例如 `1~10,15~20,30` 表示第 1–10、15–20、30 页；**按填写顺序排列**，留空则用全部页。
     （对全书太长、只想做其中几页时很有用；也能减少 OCR / 生成时间。）
   - 勾选「纯图片 PDF 启用 OCR」（扫描件必勾；有文字层的 PDF 取消勾选可大幅提速）；
     在「OCR 引擎」下拉选择 **EasyOCR、RapidOCR 或 PaddleOCR**；默认是 EasyOCR。
     并按材料选「**识别语言**」简体 / 繁体（见「六」，默认简体）。
   - 如需使用视觉大模型识别扫描页，另勾选「**使用AI OCR识别纯图片文字**」，并填写 LLM 类型、base_url、API Key、Model。
     AI OCR 会替代本地 OCR 引擎；不勾选时仍使用下面说明的本地 OCR。

2. **载入并提取文字**
   - 点「载入并提取文字」。
   - **有文字层的 PDF**：秒级提取。
   - **纯扫描件**：自动调 OCR 子进程逐页识别，进度实时显示；可中途关闭重来，已识别页会续跑不重做。
   - 勾选 AI OCR 后，纯扫描件会逐页把 PDF 页面图片发送给支持视觉输入的 OpenAI 兼容模型，返回识别文字；
     未勾选 AI OCR 时不会调用 LLM。

3. **编辑旁白（可逐段设时长）**
   - 提取完成后，页面列出每一段（=一个视频片段）的旁白文本。
   - 每段可改成你自己的解说词；留空则该片段无配音。
   - 每块右上角有「**时长(秒)**」输入框，可**单独设定该片段时长**：默认同步①里的「每片段时长」（改①会同步刷新各段），也可手动逐段调整；若开了「按解说词自动延长」，此值作为该片段的**最短**时长。
   - OCR 结果通常需要人工润色（见「六」中关于 OCR 精度的说明）。

4. **标题卡 + 配音设置 → 生成**
   - 填：主标题、副标题(期号)、徽标文字、副信息1/2、标语。
   - 封面默认使用「经典自动版式（当前）」；切换「自定义字号」可调整主标题、副标题、徽标、副信息和标语字号。右侧缩略图使用实际 PDF 第一页实时预览，最终视频与预览调用同一渲染函数。
   - 选：配音声音（云希/晓晓等 6 种中文声线）、语速（+12% ~ -20%）。
   - 选：**画面比例**（16:9 / 9:16 / 4:3 / 1:1 / 自定义）与**清晰度**（见「五」输出尺寸），网页会实时显示输出尺寸。
   - 选：**字幕**（不生成 / 生成 SRT 文件 / 烧进画面），见「五·字幕」。
   - 点「生成视频」，等进度条到 100%，页面内可直接预览并下载 MP4（选了 SRT 会多一个「下载 SRT 字幕」链接）。
   - 如果视频生成阶段失败，可以直接再次点「生成视频」重试；已完成的文字提取/OCR和旁白会复用，不会重新 OCR。只有上传或文字提取阶段失败时，才需要重新执行第①步。

## 四、新功能：按解说词自动延长片段时长

以前每个片段都是**固定**时长，旁白太长会被强行加速（听感变快、变形）。现在可开启
「**按解说词自动延长片段时长**」：

- 开启后，「每片段时长」变成该片段的**最短**时长。
- 每段画面的实际停留时间 = `max(最短时长, 该段旁白朗读时长 + 读完后留白)`，并且不超过「片段最长时长」。
- 旁白因此**按自然语速完整播放，不再被加速**；读完后画面再停留「读完后留白」秒。
- 空旁白的片段仍用「最短时长」。

新增三个参数：

| 参数 | 含义 | 默认 |
|------|------|------|
| 按解说词自动延长片段时长 | 开关；关闭时行为同旧版（固定时长、过长加速） | 关 |
| 片段最长时长(秒) | 单个片段自动延长的上限 | 60 |
| 读完后留白(秒) | 旁白读完后画面额外停留 | 1 |

> 实现要点：生成时先合成全部旁白并测得每段真实时长，再据此决定每段画面时长，
> 因此视频总时长会随解说词长短自动变化（关闭该开关则严格等于「封面 + 片段数 × 每片段时长」）。

## 五、可调参数说明

| 参数 | 含义 | 默认 | 建议范围 |
|------|------|------|----------|
| 每片段页数 | 几页 PDF 拼成 1 个画面（2 页≈对开跨页） | 2 | 1–8 |
| 每片段时长 | 每个内容片段播放秒数（开自动延长后为**最短**值）；也可在第②步**逐段单独设定** | 12 | 2–120 |
| 封面时长 | 开头标题卡停留秒数 | 3 | 0–15 |
| 封面版式 | 经典自动版式 / 自定义字号 | 经典自动版式 | — |
| 封面文字字号 | 主标题、副标题、徽标、副信息、标语 | 沿用经典比例 | 见网页输入范围 |
| 按解说词自动延长片段时长 | 见「四」 | 关 | — |
| 片段最长时长 | 自动延长上限 | 60 | 5–300 |
| 读完后留白 | 旁白读完后停留 | 1 | 0–10 |
| 画面比例 | 16:9 / 9:16 / 4:3 / 1:1 / 自定义 | 16:9 | — |
| 清晰度(短边) | 输出分辨率短边像素 | 1080 | 480 / 720 / 1080 / 1440 |
| 配音声音 | edge-tts 中文声线 | 云希(男) | 见网页下拉 |
| 语速 | TTS 速率 | +6% | +12% ~ -20% |

**时长公式**：
- 关闭自动延长：总时长 ≈ 封面时长 + 片段数 × 每片段时长。
- 开启自动延长：总时长 ≈ 封面时长 + Σ 各片段时长（每段随旁白长短自适应）。

片段数 = `ceil(总页数 / 每片段页数)`。

**输出尺寸（画面比例 + 清晰度）**：在第③步选择。
- 「清晰度」指**短边**像素；横屏时短边=高，竖屏时短边=宽。例：
  16:9 @1080 = **1920×1080**（横屏）、9:16 @1080 = **1080×1920**（竖屏，适合手机/短视频）、
  4:3 @1080 = 1440×1080、1:1 @720 = 720×720。
- 选「自定义…」可填任意 `宽:高`（如 21:9、3:4）。尺寸自动取偶数、并限制在 3840 内。
- 网页会实时显示算出的「输出尺寸」。
- **标题卡自适应**：横屏用「封面左·文字右」，竖屏/方形自动改为「封面上·文字下」堆叠居中；
  内容页统一等比缩放并居中留边（深色背景），不会变形。
- 分辨率越高越清晰但编码越慢；竖屏放横向跨页(每片段 2 页)会留很大黑边，建议竖屏时把「每片段页数」设为 1。

**字幕（可选）**：第③步的「字幕」下拉可选四种：
- **不生成字幕**（默认）。
- **生成 SRT 字幕文件**：视频旁另存 `output.srt`，生成完成后网页多一个「下载 SRT 字幕」链接。字幕是**软字幕**，不写进画面，可在剪辑软件/播放器里二次编辑。
- **把字幕烧进画面**（硬字幕）：字幕**永久烧录**在画面底部、始终显示（同时也会生成 SRT）。需要对视频重新编码，比不烧字幕稍慢。
- **中英双语硬字幕**：中文在上、AI 翻译的英文在下，同时生成包含中英文两行的 SRT。中文使用微软雅黑粗体，英文使用 Arial 粗体，并带深色描边。

字幕**内容取自第②步「编辑旁白」**（你怎么改，中文字幕就是什么）。时间轴按每段旁白的实际配音时长自动排布，长句会自动按标点/长度切成多条短字幕。硬字幕可选择中文、英文和描边颜色，选择结果保存在浏览器本地。

双语模式复用 LLM 类型、base_url、API Key 和 Model 配置，以最多 8 条字幕为基础批次生成英文翻译；若模型少返回或返回截断 JSON，会自动拆成更小批次补译。单条仍失败时只跳过该条英文、保留中文并继续生成视频。选择 NVIDIA 时会继续使用节流与限流重试。双语字幕不改变中文旁白和配音，只增加英文字幕。LLM 配置仍只保存在浏览器 localStorage 和当前本地任务内存中，不写入项目文件。
> 若某台机器烧录失败（字体/滤镜问题），程序不会整体失败：会输出**无硬字幕**的视频并保留 `.srt`，同时在服务端日志给出提示。

## 六、OCR 说明（纯图片 PDF 必读）

《大众电影》这类**扫描件没有文字层**，必须靠 OCR 把图片里的字识别出来。三种本地 OCR
都跑在**独立子进程** `_ocr_worker.py` 里，主进程只负责调度与收集结果。

### 本地 OCR 引擎

网页第①步的「OCR 引擎」下拉框提供三种选择：

- **EasyOCR**：当前默认，依赖 `torch`，模型成熟；如果遇到 Windows 原生库崩溃，可改用 RapidOCR。
- **RapidOCR**：基于 ONNX Runtime，依赖较轻，通常更适合不想使用 PyTorch 的 Windows 环境。
- **PaddleOCR**：对中文印刷体和复杂版面通常更有优势，但依赖较大，安装和版本匹配要求更高。

只会加载当前选择的引擎；例如选择 RapidOCR 时，worker 不会导入 EasyOCR/PyTorch。
三种引擎都复用相同的 PDF 渲染、逐页结果文件、断点续跑和卡死保护流程。

### AI OCR（可选）

网页第①步勾选「**使用AI OCR识别纯图片文字**」后，程序只在没有文字层、原本需要 OCR 的扫描 PDF 上调用视觉大模型，
逐页发送压缩后的页面图片，并把模型返回的文字放入第③步编辑框。已有文字层的 PDF 仍直接提取文字。

- AI OCR 与「使用AI自动生成旁白」是两个独立开关，可以只使用 AI OCR，也可以同时使用。
- 两个功能共用 LLM 类型、base_url、API Key 和 Model 配置；模型必须支持图片输入（vision）。
- 选择 NVIDIA 时，AI OCR 和 AI 旁白请求都会自动按免费 API 的请求频率节流；每一页通常至少对应一次 API 请求。
- 配置只保存在浏览器 localStorage，并在请求时传给本地服务，不会写入项目文件或提交到 GitHub。
- AI OCR 需要网络和可用的视觉模型 API；单页请求失败时会保留该页原有结果并继续，服务端日志会记录失败原因。

### 识别语言：简体 / 繁体（不是自动的，要选）

网页第①步的「**识别语言**」下拉可选：
- **简体中文 + 英文**（默认，`ch_sim`+`en`）——大陆版《大众电影》选这个。
- **繁体中文 + 英文**（`ch_tra`+`en`）——港台/繁体材料选这个。

说明：EasyOCR 的简体与繁体是**两套不同模型**，简体模型识别繁体字会大量出错；且**不能把简体和繁体
放进同一次识别**，只能二选一（各自都可搭配英文）。**首次**选繁体会联网下载繁体模型
（`chinese.pth`，约 80MB），下载后即可离线；简体模型（`zh_sim_g2.pth`）你已下载过。

### 运行机制

- **子进程隔离**：OCR 引擎依赖偶发崩溃不会拖垮 Web 服务；主进程会重新拉起子进程。
- **断点续跑**：识别结果按页写入任务目录下的 `ocr.txt`（`========== PAGE n ==========` 分隔并即时 flush）。
  已完成的页会跳过，中途崩溃/关网页/重启服务都不会重做已识别的页。
- **一次加载、批量识别**：一次子进程会处理「所有剩余页」，把所选引擎的初始化成本
  只付一次，而不是每几页就重载一遍模型。
- **卡死保护**：若连续 3 次子进程都没有推进任何一页（环境损坏 / 模型缺失 / 某页恒定崩溃），
  会**报明确错误并停止**，不会像以前那样无限重试、任务永远卡在「OCR 识别中」。
- **单页容错**：某一页识别异常时写入空结果并继续下一页，不影响整体进度。
- **并发安全**：`ocr.txt` 放在各任务自己的目录下，同时处理多个 PDF 不会互相覆盖。

### 性能预期（本机 CPU、无 GPU 参考值）

- **首次启动时间**：单个 OCR 子进程需要加载所选引擎和模型；EasyOCR/PaddleOCR 通常比 RapidOCR 更重，
  具体时间取决于机器和模型缓存。
- **每页约 15~30 秒**，取决于版面复杂度与渲染分辨率。整本 46 页大致 **15~25 分钟**。
- 进度条会实时显示「OCR 识别中 x/N 页」。

### 首次使用可能需要联网下载模型

EasyOCR 首次运行会下载识别模型（约 100+ MB）到用户目录 `~/.EasyOCR/model/`
（Windows 为 `C:\Users\<你>\.EasyOCR\model\`，含 `craft_mlt_25k.pth`、`zh_sim_g2.pth`）。
RapidOCR 会使用 ONNX 模型，PaddleOCR 也可能在首次运行时准备模型；具体目录由对应库决定。
**首次务必联网**；模型准备后即可离线 OCR。若模型缺失又无网络，OCR 会连续失败并按上面的
「卡死保护」报错退出。

### 识别精度

- 现在直接用内存图像喂给所选 OCR 引擎（不再中转 JPEG、也不再残留临时图片），渲染 150dpi、
  `canvas_size=1024`——这是在**本机（内存偏紧）**上实测**稳定且比旧版 800 清晰**的折中值。
  但**扫描杂志版面复杂**（竖排、艺术字、图文混排），OCR 结果仍会有错字、乱序、漏字，
  **需要在第 3 步人工润色**，或直接改写成你自己的解说词。
- EasyOCR 内存充裕的机器想更准，可在 `_ocr_worker.py` 里调大 `CANVAS_SIZE`（如 1280/1600/2560）与
  `RENDER_ZOOM`——更准但更慢、更耗内存。**注意**：本机在 `CANVAS_SIZE=2560` 时会因内存不足
  （OOM / 段错误）导致该页识别失败；若遇到 `not enough memory` 或崩溃，请把它调小。

## 七、依赖与环境（安装步骤见「二」）

## 八、常见问题

- **Q：`py -3.14 app.py` 运行后什么都没显示？**
  A：先看有没有打印"启动自检"那几行：
  ① 完全没输出 → 多半是 Python 没装好或版本不对（`py -3.14 --version` 验证；没有 `py` 就用 `python`）。
  ② 自检里某项显示"缺失" → 按「二」补装对应依赖 / ffmpeg。
  ③ 自检和"启动服务"都打印了，但浏览器打不开 → 端口 5005 被占用或被防火墙拦截，换端口或放行。

- **Q：选择 OCR 后长时间卡在进度 0%？**
  A：进度 0% 时会显示"正在加载所选 OCR 模型并识别首页…（已 N 秒）"，**带秒数会一直跳动**，说明没死、在干活。
  OCR 子进程要先加载所选引擎和模型，出第一页后进度就按页递增（33%→66%→…）。
  防卡死机制：
  ① 已准备好的模型不会重复下载；
  ② **看门狗**——若 5 分钟内一页都没出（疑似卡在加载/联网/某页），自动杀掉重试，最多 3 次仍无进展
     就**报明确错误**（不会永远转圈）。
  若最终报错，常见原因：对应引擎依赖未安装、模型下载失败、内存不足，或 Python/引擎版本不兼容。
  > 首次在新机器上用 OCR：`~/.EasyOCR/model/` 还没有模型时，Reader 初始化会联网下载（约 100+MB），
  > 这一步需要联网，网络差会较久；模型准备好后即可离线运行。

- **Q：生成视频时报"TTS 连接微软语音服务失败 / 无法连接 bing.com"？**
  A：配音用的 edge-tts 需要访问微软的 `speech.platform.bing.com`。公司网络/防火墙/代理挡住它就会报这个错。
  处理办法：① 换一个能正常上网的网络（或挂可用代理）后重试；② 确认系统代理设置正确。
  说明：**个别**片段偶发失败会自动改为该片段静音并继续；只有**所有**旁白都失败（整体连不上）时才会报错中止。

- **Q：OCR 很慢？**
  A：CPU 上识别速度取决于所选引擎和页面复杂度。可减少页数或先在有文字层的 PDF 上关掉 OCR；
  RapidOCR 通常启动更轻，PaddleOCR 可能识别更好但初始化更重。GPU 是否可用由各引擎及其依赖单独决定。

- **Q：三种本地 OCR 怎么选？**
  A：EasyOCR 是默认兼容路径；RapidOCR 更轻且不依赖 PyTorch，适合遇到 Torch 原生崩溃的机器；
  PaddleOCR 通常更适合中文印刷体和复杂版面，但安装依赖更重。先安装对应依赖，再在网页「OCR 引擎」下拉框选择。

- **Q：OCR 结果有很多错字/乱序？**
  A：扫描杂志版面复杂，OCR 难免出错。请在第 3 步「编辑旁白」里润色，或改写为自己的解说词。

- **Q：网页里能预览，但下载后用播放器打开报"格式不对"？**
  A：已修复。原因是旧版输出的 MP4 把 `moov` 头放在文件末尾（网页可边下边播，但很多本地播放器要先读文件头，读不到就报错）。
  现在合成时加了 `-movflags +faststart`，把头移到文件开头，下载后各播放器都能正常打开。**重新生成一次**即可（旧文件请重做）。

- **Q：旁白读到一半就被切掉 / 听起来加速变形？**
  A：说明该段旁白比片段时长长。① 开启「按解说词自动延长片段时长」让画面等旁白读完；
  ② 或调大「每片段时长」；③ 或把旁白写短些。

- **Q：结尾有一段静音？**
  A：某段旁白过短会补静音。把该段写长些，或开启自动延长（空旁白仍按最短时长）。

- **Q：封面/标题文字显示为方框乱码？**
  A：确认 `font.ttf` 与本应用在同一目录；该字体为楷体，含常用汉字。

- **Q：多人/远程访问？**
  A：默认仅监听 `127.0.0.1`。如需同局域网访问，把 `app.py` 里 `host="127.0.0.1"` 改为
  `host="0.0.0.0"`（注意安全风险，仅可信网络使用）。

```bat
py -3.14 _selftest.py
```

会构造一个**带文字层**的测试 PDF（跳过 OCR），跑通 上传→提取→生成→下载，
产出约 7 秒的测试 MP4 并用 ffprobe 校验，最后打印 `SELFTEST OK`。
（该自检不覆盖 OCR；要验证 OCR，请在网页上传真实扫描件并勾选 OCR。）
